### 示例：PRD-2026-001 设备首次配对（OTA 激活流程）

| 字段 | 值 |
| --- | --- |
| 文档 ID | PRD-2026-001 |
| 版本 | v0.2 |
| 负责人 | @you |
| 状态 | 评审中 |
| 关联 RFC | RFC-004 设备身份 |
| 目标发布 | 2026-08-15 |

**业务问题**：
NAS 重装系统后，所有客户端设备需要重新走 SSH 手动配对，平均 15 分钟，期间 NAS 处于"半脱管"状态。

**产品目标**：

- [ ] 设备首次配对耗时 < 2 分钟（含扫码）
- [ ] 配对成功率 > 95%（LAN 环境）
- [ ] 失败可自助重试，无需重启 NAS 守护进程

**非目标**：

- 不做多用户/多 Owner
- 不做跨账号转移
- 不做 UI 主题切换

**用户与场景**：

| 角色 | 关键特征 | 核心诉求 | 当前痛点 |
| --- | --- | --- | --- |
| Owner（自用） | 唯一管理员 | 极简步骤 | 每次都忘命令、查笔记 |

**核心场景**：

1. NAS 重装后第一次启动守护进程，签发短期 token
2. 终端打印 QR + 6 位短码
3. 手机扫码确认绑定
4. 客户端拉取设备清单，完结

**用户故事**：

| ID | 故事 | 优先级 | 关联 AC |
| --- | --- | --- | --- |
| US-005 | 守护进程签发短期 token | P0 | AC-F1~3 |
| US-006 | CLI 打印 QR + 短码 | P0 | AC-F4~5 |
| US-007 | 手机扫码绑定 | P0 | AC-F6~9 |
| US-008 | 失败重试 + 降级 | P1 | AC-E1~3 |

**功能列表**：

| ID | 功能 | 描述 | 优先级 | 依赖 | 估时 |
| --- | --- | --- | --- | --- | --- |
| F-001 | 守护进程启动签发 token | Ed25519 短期 token（TTL 5min） | P0 | - | 0.5d |
| F-002 | CLI 暴露 QR / 短码 | 终端打印 QR + 6 位短码 | P0 | F-001 | 0.5d |
| F-003 | 手机端扫码绑定 | Expo 客户端轮询激活 | P0 | F-001 | 2d |
| F-004 | 失败重试与降级 | 提示重扫 / 改手动 IP | P1 | F-002 | 1d |

**高层验收标准**：

- [ ] AC-G1：完整 happy path 端到端通过
- [ ] AC-G2：CLI / 移动端日志不打印完整 token
- [ ] AC-G3：LAN + 弱网（2G 模拟）下均可完成

**边界场景**：

| 场景 | 期望行为 |
| --- | --- |
| token 过期（>5min） | 提示用户按回车刷新，CLI 自动重签 |
| 手机不在同 LAN | 降级为手动输入 token + 公网 IP |
| 重复扫码 | 提示是否替换旧绑定（Owner 确认后覆盖） |
| QR 被污损 | 客户端报错，提示重新生成 |

**风险与依赖**：

| 风险/依赖 | 影响 | 缓解措施 |
| --- | --- | --- |
| Tailscale 抖动 | LAN 探测失败 | mDNS + 公网 fallback |
| Expo EAS 升级 | 构建脚本失效 | 锁版本 + CI 周构建 |
| QR 库跨平台 | iOS 偶发识别失败 | 备选 ZXing + 短码兜底 |

**变更记录**：

| 日期 | 版本 | 变更人 | 变更内容 |
| --- | --- | --- | --- |
| 2026-07-20 | v0.1 | @you | 初稿 |
| 2026-07-23 | v0.2 | @you | 补充失败重试流程 + 非目标 |

## 2. 用户故事模板

### 模板

```text
US-XXX：[一句话标题]

As a <角色>
I want <能力>
So that <价值>

验收标准（Given / When / Then）：
- Given <前置>
  When <动作>
  Then <结果>
- Given …
  When …
  Then …

估时：<X d>
优先级：<P0 / P1 / P2>
依赖：<US-XXX / 无>
备注：<可选>
```

### 字段说明

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| ID | ✓ | 格式 `US-XXX`，三位序号 |
| 标题 | ✓ | 一句话动宾结构 |
| 角色 | ✓ | 具体角色名，不用"用户" |
| 能力 | ✓ | 用户能完成的动作 |
| 价值 | ✓ | 对角色/业务的价值，避免"更方便"等空话 |
| 验收标准 | ✓ | 至少 1 条 Given/When/Then |
| 优先级 | ✓ | P0=必须有 / P1=应有 / P2=最好有 |
| 估时 | ✓ | 人·天 |
| 依赖 | × | 阻塞的 US |

### INVEST 自检清单

| 原则 | 含义 | 自检 |
| --- | --- | --- |
| I | Independent | 不依赖其他故事也可独立排期？ |
| N | Negotiable | 描述是结论而非死命令？ |
| V | Valuable | 对用户/业务有可感知价值？ |
| E | Estimable | 能估时？ |
| S | Small | 一个迭代内能完成？ |
| T | Testable | 有明确 AC 可验收？ |

### 示例：US-007 通过手机扫码完成 NAS 设备配对

**As a** NAS Owner
**I want** 在手机端扫描 NAS CLI 输出的二维码完成设备绑定
**So that** 重装系统后 2 分钟内恢复远程控制能力，不用 SSH 进 NAS

**验收标准**：

- Given NAS 守护进程刚启动并打印了配对 QR
  When 我在手机客户端点击"添加设备"并扫描 QR
  Then 客户端展示设备名称、IP、token 摘要，2 秒内跳转到"已绑定"页
- Given QR 中 token 已过期（>5min）
  When 我尝试用该 QR 绑定
  Then 客户端显示"配对码已过期，请到 NAS 终端按回车刷新"，并提供"复制刷新命令"按钮
- Given 手机与 NAS 不在同一 LAN
  When mDNS 探测失败
  Then 客户端自动 fallback 到手动输入 token，并提示输入 NAS 公网 IP
- Given 同一 Owner 已绑定过该 NAS
  When 我再次扫码
  Then 客户端弹出"已绑定，是否替换？"二次确认

**估时**：2 d
**优先级**：P0
**依赖**：US-005（守护进程签发 token）
**备注**：token TTL 与 RFC-004 §3.2 对齐

## 3. 验收标准清单（Acceptance Criteria Checklist）

> 提测 / 验收时逐项过。建议贴 PR 描述里当 checklist。

### A. 功能性

| # | 检查项 | 通过条件 |
| --- | --- | --- |
| F1 | 主流程 | 100% 走通 happy path，无报错 |
| F2 | 每个按钮 / 命令 | 都有预期响应（无 no-op） |
| F3 | 状态变更 | UI 与后端状态一致（无幽灵状态） |
| F4 | 错误提示 | 用户能看懂下一步怎么操作 |

| F7 | 取消 / 返回 | 中途退出不留半成品状态 |

### B. 性能

| # | 检查项 | 通过条件 |

## 4. 优先级评估框架

### 4.1 RICE（团队 / 多用户场景）

| 维度 | 含义 | 取值 |
| --- | --- | --- |
| **R**each | 一个周期内触达多少用户 / 设备 | 整数 |
| **I**mpact | 对单用户的影响强度 | 3=巨大 / 2=高 / 1=中 / 0.5=低 / 0.25=微小 / 0=无 |
| **C**onfidence | 对 R/I/E 的信心 | 100% / 80% / 50% |
| **E**ffort | 人·周（含设计 / 开发 / 测试 / 文档） | 整数 |

**公式**：`RICE Score = (R × I × C) / E`

> Yuzu-GCA 适配：Reach 改用"一个发布周期内会触发该功能的设备数"。

### 4.2 ICE（轻量版 / 需求池筛选）

| 维度 | 含义 | 1-10 |
| --- | --- | --- |
| **I**mpact | 业务 / 用户价值 | 1-10 |
| **C**onfidence | 成功把握 | 1-10 |
| **E**ase | 实现成本反向（越高越容易） | 1-10 |

**公式**：`ICE = (I + C + E) / 3`

> 适合需求池里几十个候选快速拍优先级，不区分人力。

### 4.3 WIE（Yuzu-GCA 自用，单人项目）

| 维度 | 含义 | 1-5 |
| --- | --- | --- |
| **W**ish | 我自己想不想用 | 1-5 |
| **I**ndependence | 是否依赖外部不可控因素 | 1=完全依赖 / 5=完全自主 |
| **E**ffort | 工作量反向（越高越轻） | 1=一周+ / 5=几小时 |

**公式**：`WIE = (W × I) + E`（满分 30）

> 适合个人项目快速排序"我今晚做哪个"。

### 阈值参考

| 决策 | RICE | ICE | WIE |
| --- | --- | --- | --- |
| 立即做 | > 10 | > 7 | > 20 |
| 排期做 | 4-10 | 5-7 | 12-20 |
| 砍 / 推迟 | < 4 | < 5 | < 12 |

### 示例：RICE 排序 Yuzu-GCA 三个候选

| 候选 | Reach（设备数/季） | Impact | Confidence | Effort（人·周） | RICE | 排名 |
| --- | --- | --- | --- | --- | --- | --- |
| 设备首次配对扫码 | 5 | 3 | 100% | 1.0 | **15.0** | 🥇 |
| CLI 命令自动补全 | 8 | 2 | 80% | 0.5 | **12.8** | 🥈 |
| 完整 Web 控制台 | 5 | 1 | 50% | 4.0 | **0.625** | 🥉 |

**决策**：

- **Phase 1**：设备配对（RICE 最高，且阻塞其他所有功能）
- **Phase 1.5**：CLI 自动补全（自用高频 + 成本极低）
- **推迟**：Web 控制台（依赖多、Impact 低、自用 CLI 已够）

### 示例：WIE 排序"今晚做哪个"

| 候选 | Wish | Independence | Effort | WIE |
| --- | --- | --- | --- | --- |
| 修 CLI `--help` 输出错位 | 5 | 5 | 5 | **30** |
| 写 OTA 签名校验 | 5 | 3 | 3 | **18** |
| 加 Web UI 暗色主题 | 2 | 5 | 4 | **14** |

**决策**：今晚做 `--help`（半小时搞定，纯自用，受益明显）。

## 5. 需求澄清问题清单

> 接到一句"我想要 X"时，按下面顺序问。**3 分钟拿 80% 关键信息**。

### 5.1 目标

- [ ] 这个需求要解决的**根问题**是什么？目前怎么应对？
- [ ] 成功的**衡量标准**是什么？（可量化：耗时 / 成功率 / 留存）
- [ ] 如果只能交付**一个数字**改善，你选哪个？
- [ ] 和**现有 X 功能**是什么关系？（替代 / 补充 / 独立）
- [ ] **不做**会有什么后果？谁会痛？

### 5.2 用户

- [ ] **谁**会用？（角色 + 数量 + 使用频率）
- [ ] 用户当前用**什么替代方案**？
- [ ] 用户愿意为这个需求**改习惯**吗？还是必须无感？
- [ ] 是否有**反对者**？谁？为什么？

### 5.3 场景

- [ ] **主流程**走一遍：从打开应用到完成，需要几步？
- [ ] **何时**用？（早 / 中 / 晚 / 周中 / 周末 / 紧急 vs 日常）
- [ ] **在哪**用？（办公室 / 路上 / 家里 / 桌面 / 手机 / CLI）
- [ ] **配合**使用的东西是什么？（边听歌边用 / 边开会边用）

### 5.4 边界

- [ ] **最少必要**输入是什么？（用户最懒能懒到什么程度）
- [ ] **失败**了怎么办？（重试 / 降级 / 回滚 / 留半成品）
- [ ] **重复操作**会发生什么？（幂等 / 覆盖 / 报错）
- [ ] **并发**场景？（多人同时操作会怎样）
- [ ] **离线 / 断网**时表现？
- [ ] **错误信息**用户能看懂吗？需要"下一步该做什么"吗？

### 5.5 约束

- [ ] **截止时间**硬性还是软性？
- [ ] **预算 / 人员**有多少？（1 人 1 周 vs 3 人 1 月）
- [ ] **技术栈 / 平台**必须用什么？不能用什么？
- [ ] **依赖**的外部服务 / 库稳定吗？有备选吗？
- [ ] **数据 / 隐私**约束？（GDPR / 等保 / 个人自用 = 宽松）
- [ ] **可逆性**：做错了能回滚吗？回滚成本？
- [ ] **上线方式**：灰度？开关？强制升级？

### 5.6 输出

- [ ] 有**参考产品**吗？哪里像、哪里不像？
- [ ] 有**设计稿 / 原型**吗？哪怕是手画？
- [ ] 验收时**谁来 demo**？给谁看？

### 示例：用户说"我要做个设备配对功能"

| 分类 | 问题 | 用户的回答 |
